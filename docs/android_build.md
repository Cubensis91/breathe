## Current status

**BLOCKED — REQUIRES PC** (for now; not re-attempted on-device yet beyond

As of Milestone 0/1 bootstrap, this environment (Ubuntu 26.04 arm64 under
Termux `proot-distro`) has:

- No Java installed (`openjdk-25-jdk-headless` available via `apt`, not yet

- No Android SDK / build-tools / platform-tools installed.
- No `adb`.
- Godot Android export templates **not downloaded** (the official `.tpz` is
  ~1.2 GB; deferred until this milestone is actually worked on).

## What would be needed to attempt an on-device export

1. Install a JDK (`apt-get install openjdk-25-jdk-headless` or similar).
2. Obtain Android SDK command-line tools + platform-tools + build-tools
   compatible with arm64 Linux (Google's official `cmdline-tools` package is
   published for Linux x86_64 primarily — arm64 host support needs
   verification; this is the main open question, not yet resolved).
3. Download and install Godot's Android export templates
   (`Godot_v4.7.1-stable_export_templates.tpz`) into
   `~/.local/share/godot/export_templates/4.7.1.stable/`.
4. Configure the Godot Android export preset (debug keystore is
   auto-generated by Godot on first Android export if none is configured).
5. Run `godot4 --headless --export-debug "Android" <output>.apk` from the
   project directory.
6. Install/run the resulting APK on the device to verify (`adb install` or
   direct install if `adb` isn't available on this device).

Step 2 is the real unknown — it has not been verified on this arm64 proot
environment and is not assumed to work. If/when this milestone is picked up,
verify step 2 first before investing further; if it fails, document it and
move Android export fully to the PC per `docs/pc_handoff.md`.

## Recommended path

Given the JDK/Android SDK arm64-host uncertainty and the tight RAM on this
device, the pragmatic default is: **develop and test game logic headlessly
on-device, and perform the actual Android export/signing/install/playtest
cycle on the PC** (Milestone 16), where Godot Editor + Android SDK setup is
standard and well-supported. This on-device path is not abandoned — it may
be revisited if there's a specific reason to prove it out — but it is not on
the critical path for making progress on BREATHE.

## Manual Android verification checklist (for whichever build produces an APK)

```
Install APK.
Launch BREATHE.
Hold the screen.
Confirm the creature rises.
Release.
Confirm the creature descends.
Repeat rapidly.
Confirm responsiveness.
Collide intentionally.
Confirm death.
Confirm restart.
```
